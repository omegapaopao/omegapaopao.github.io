阿伟的智能龟缸

乌龟是变温动物，代谢速率和免疫能力都挂在水温上。水温偏离适宜区间超过两小时，呼吸道感染的相对风险明显上升。原来的做法是一支本地温度计，读数靠人看，昨天多少度没人知道。

现在这条链路有四层，每层用最合适的语言：芯片上跑 C++ 采样，PC 上跑 Python 桥接，云端跑 Node.js 写库，屏幕上跑小程序画图。

感知层 ESP32-C3 · DS18B20 · C++ / ARDUINO CORE

每 5 秒采一次水温，通过 BLE 5.0 GATT 通知广播出去。分辨率 0.0625 °C，设备名默认 TurtleSensor。

边缘桥接层 PYTHON 3.12 · ASYNCIO · BLEAK · AIOHTTP · SQLITE WAL

PC 上的常驻进程，生产者消费者模式：Bleak 异步订阅蓝牙特征，SQLite 以 WAL 模式落盘，aiohttp 开局域网 REST 接口给小程序，同时把每个采样周期 POST 到云端。

云原生服务层 NODE.JS 18 · CLOUDBASE · 云函数 · 静态托管 CDN

文档数据库存全量时序；写入代理把最新温度同步成静态快照推上 CDN，远端读取压到 200 ms 以内；云函数做 HTTP 中继，绕开小程序的域名白名单限制。

交互呈现层 微信小程序 · MVVM · CANVAS 2D

3 秒轮询的实时仪表盘，温度到色彩四级映射；Canvas 2D 画时序曲线，1 小时 / 6 小时 / 24 小时 / 7 天四个窗口切换，自动标出峰值和谷值。

铁记

力量训练要记的东西很固定：重量、组数、次数。记完得看出来有没有进步，所以最大力量用 Epley 公式实时推算，训练容量自动出，长期变化交给折线图和日历热力图。

没有后端服务器。小程序原生加云开发，数据库、存储、云函数都在云上，客户端直连。它没有用户增长计划，起点就是作者自己训练时需要。

EPLEY 1RM实时推算

1RM = w × (1 + r / 30)

w 为重量，r 为次数。输入即出结果，不需要按保存。

四个项目，同一条做法

这些不是写在前言里的原则，是从 commit 和 README 里能对上的四个事实。

零依赖优先

made in heaven 把所有功能压进 19 KB，一个依赖都没有，装进 Tampermonkey 就行。dsh-open-design 反过来有 2.6 MB，但那全是纯文本文件，没有运行时依赖，使用时也不发网络请求。能自己写完的就不引包。

从自己的问题开始

铁记的起点写在 README 第一段：「纯属自己训练时需要，顺手写的」。龟缸的起点是室友想知道水温，而一支温度计不会告诉你昨天多少度。四个项目没有一个是先想好要做什么再去找场景的。

分层解耦，每层用对的语言

龟缸四层各写各的：C++ 烧进芯片，Python 在 PC 上桥接，Node.js 在云上写库，JavaScript 画小程序，层与层之间只有 BLE 通知、HTTP 和 CDN 三个接口。铁记更彻底，直接把后端服务器砍掉了。

把验收标准写成代码

dsh-open-design 把设计门禁做成了 od-check.mjs，逐条跑。仓库里还留了一对夹具，违规页必须失败、合规页必须通过，这样检查不会退化成一条永远绿的命令。

长动效走 ANIMATION

门禁把 transition 的时长按交互 300ms、上限 800ms 卡死，但不检查 animation。所以凡是需要慢下来看的东西，网格地板、跑马灯、流光、点阵波、幽灵字视差，全部走 keyframes，transition 只留给按钮和悬停反馈。

视差是渐进增强

滚动驱动动画包在 @supports (animation-timeline) 里。支持的浏览器上幽灵标题会随滚动漂移、顶部有进度条；不支持的浏览器拿到的是完整可读的静态版本，没有任何东西依赖它才能看见。

四个颜色是四台机器

琥珀是速度，信号红是水温，青柠是铁，青绿是设计系统。颜色只在自己模块里出现，页面骨架始终是碳黑加单色。全站没有一处紫色渐变，也没有一张位图。
